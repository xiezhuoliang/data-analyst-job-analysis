# 数据清洗方案：51job 数据分析岗位招聘数据

## 前提说明

原始数据：`51job_数据分析_完整版.csv`（1495 行 × 14 列，2025\-09 \~ 2026\-07，5 个城市组各约 300 条）
本文档同时作为 GitHub 仓库 `docs/cleaning_plan.md`，清洗完成后把实际规则回填，即成为 README 的「数据处理」章节素材。



## 数据现状盘点

### 1\.1 结构性问题（优先解决）

||问题|规模|说明|
|---|---|---|---|
|P1|`工作地点` 整列缺失|1495/1495（100%）|可从详情链接 URL 中的城市拼音恢复 1479 条|
|P2|薪资单位混用|1482 条有效薪资中：纯「千」463、纯「万」593、跨单位「8千\-1\.5万」421、年薪「万/年」71、日薪「元/天」4、开放式「3千及以下」1|另有 392 条带「·N薪」，13 条整体缺失|
|P3|岗位相关性噪音|约 562 条（37\.6%）职位名不含数据/分析语义|运营专员、财务顾问、管培生、票务岗等混入|
|P4|疑似重复发布|224 行「公司\+职位\+薪资\+描述」完全重复；223 个重复组中 199 组连发布时间都相同|基本可以判定为爬虫分页/翻页重复抓取，而非真实多发|

### 1\.3 质量良好、无需动刀的字段

- `详情链接`：0 重复，全部可解析；发布时间解析失败 0

- `公司性质`（9 类）、`公司规模`（7 档）：取值规范，直接可用

- `福利标签`：320 种标签，「五险一金/年终奖金/带薪年假」领跑，做词频分析素材充足

- 城市组间样本量均衡（298\~300），适合做分组对比

## 清洗思路与步骤

按依赖关系排序，共 6 步。每步输出一个中间版本（`data/interim/step{N}_*.csv`），保证可回溯

### Step 1｜岗位相关性过滤

为什么放第一步：噪音岗位会污染后续所有统计口径，先圈定分析集再清洗最省力气。

三层分桶，不直接删，而是打标：

|桶|判定规则|条数|用途|
|---|---|---|---|
|A 核心岗|职位名含「数据分析 / Data Analyst」|394|主分析集|
|B 数据相关岗|含「数据 / BI / 经营分析 / 商业分析 / 数据运营 / 数据挖掘」等|539|扩展分析集（技能、薪资带宽分析）|
|C 噪音岗|其余（运营、财务、产品、销售等）|562|剔除出主分析，单独存档|

- 输出字段：`job_category ∈ {core, related, noise}`

### Step 2｜去重

规则（按优先级）：

1. 主键：`公司名(标准化后) + 职位名(标准化后) + 薪资 + 职位描述` 完全一致 → 保留第一条

2. 公司名标准化：去空格、全角括号转半角（`菲斯科（上海）软件` 这类带地区括号的保留括号内容，避免误并不同公司）

3. 对 Step 1 的三个桶分别去重，桶 C 的重复直接随剔除丢弃

- 预期：主分析集（A\+B）去重后约 780\~800 条

- 输出字段：无新增，行数减少；保留 `dup_count` 列记录该岗位原始出现次数（「同一岗位发几次」本身可作为企业招聘急迫度的代理变量）

### Step 3｜城市恢复与归一化

1. 从 `详情链接` 提取：`jobs.51job.com/{city_pinyin}/` → 覆盖 1479 条

2. 区县级拼音归并到地级市（77 条）：

    - `kunshan / changshu / zhangjiagang / taicang` → 苏州

    - `guanchenghuizuqu / zhongyuanqu / jinshuiqu / xingyangshi / gongyishi` → 郑州

    - `hadongbin`（拼写变体）→ 哈尔滨

3. `all`（3 条，全国/远程岗）→ 从职位名提取 base 地（如「战略分析师（base苏州」），提取不到则标「未知」

4. 企业子域名链接（16 条，如 `koch.51job.com`）URL 无城市 → 标「未知」，分析时剔除或单独说明

5. 拼音 → 中文映射表（约 30 个城市，手工维护一个 dict，放 `src/city_map.py`）

6. 新增分析字段：`城市等级`（一线/新一线/二线，按 2026 年主流城市分级名单）

- 输出字段：`城市(中文)`、`城市等级`、`city_source ∈ {url, title, unknown}`（记录来源，便于质检抽检）

- 验证动作：随机抽 20 条，人工核对链接城市与真实岗位地点一致——这步写进 README 的「数据质量验证」小节

### Step 4｜薪资标准化

统一换算为 月薪中位数（万元/月），规则：

|原始模式|示例|换算规则|
|---|---|---|
|`A千-B千`|8千\-1\.2万 → 下 8 千、上 1\.2 万|千 ÷ 10 → 万|
|`A万-B万`|1\.5\-2万|直接用|
|`A千-B万`|8千\-1\.5万|分别按单位换算|
|`A-B万/年`|25\-38万/年（71 条）|÷ 12 转月薪|
|`N元/天`|900元/天（4 条，多为实习岗）|× 21\.75 天 → 月薪，并打 `is_intern=1` 标记（日薪岗基本是实习/兼职）|
|`3千及以下`|1 条|上限=3 千、下限缺失 → 用上限 × 0\.8 估下限，或单独剔除（量小，建议剔除并在文档声明）|
|`·N薪`|8千\-1万·13薪（392 条）|拆出 `薪月数` 列；主口径用**月薪**（便于横比），另算 `年薪中位 = 月薪中位 × N` 作为补充口径|

- 输出字段：`薪资下限(万)`、`薪资上限(万)`、`月薪中位(万)`、`薪月数`、`is_intern`、`年薪中位(万)`

- 13 条薪资缺失 → 薪资相关分析中剔除，其余分析保留

- 边界检查：换算后月薪中位 \< 0\.3 万或 \> 15 万的行逐一人工过目（防解析错误）

### Step 5｜经验 / 学历分档

经验要求 30 种写法 → 数值化 \+ 分档：

- 解析为 `经验下限(年)`、`经验上限(年)`（「3年及以上」→ 下 3、上 NaN；「无需经验」→ 0/0）

- 分档：`应届/无需经验（0）`、`1-3年`、`3-5年`、`5-10年`、`10年以上` → `经验档位`

- 缺失 0 条，无需补缺

学历要求 → 有序分类：

- `高中/中技中专 < 大专 < 本科 < 硕士 < 博士`，保留原字段 \+ 新增 `学历层级(1-5)` 数值列（方便算相关性和画堆叠图）

- 缺失 25 条 → 标「未知」，层级列置 NaN

### Step 6｜文本字段清洗与任职要求回收

1. `职位描述`、`任职要求`：去 `\t`、`\r`、连续空白、`61\t` 类乱码编号、首尾「岗位职责：」等冗余标题词

2. 任职要求回收：对缺失的 860 条，用正则 `(任职要求|任职资格|岗位要求|职位要求|应聘要求|我们需要)[:：]?` 切分 `职位描述`，命中的后半段填入 `任职要求`（回收 481 条，回收后缺失率从 57\.5% 降到约 25%）

3. 切分动作本身会截断 `职位描述` → 保留 `职位描述_raw` 原列不动，切分结果写新列，原始列永不覆盖

4. 福利标签：统一分隔符为 `|`，去空格，生成 `福利列表`（list 列存 JSON 字符串）

5. 超长描述（\> 3000 字，约个位数）保留但打 `long_desc=1` 标记（多为 JD 模板复制了公司介绍）
