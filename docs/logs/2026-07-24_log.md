## 工作流程

### 第一步：找接口

- 原计划用 F12 抓包，但 51job 前端有反调试，一打开 F12 就无限弹 debugger，页面卡死。
- 改用 Chrome 自带的 `chrome://net-export` 录网络日志（系统层面抓，JS 检测不到）。
- 录完后导出 .json，用 Python 解析，成功定位接口：`https://we.51job.com/api/job/search-pc`

### 第二步：分析接口参数

- `jobArea` 是城市代码，一次可传 5 个城市，逗号隔开
- `sign`、`user-token`、`uuid` 绑定，直接从日志复制到 Python 里用
- `decode__1048` 加密参数会过期，纯 requests 请求过一会儿就被 WAF 拦截

### 第三步：绕过 WAF

- 放弃纯 requests，改用 **Selenium + Edge**
- 先打开搜索页让浏览器自动完成 WAF 验证，然后在页面里注入 fetch 调接口
- 浏览器自带的 Cookie、签名全在，WAF 认不出来是爬虫
- **踩坑**：fetch 里手动写了 Referer 头，含中文报编码错。删掉自定义 Referer，让浏览器自己带，问题解决

### 第四步：确定 25 个城市分组

51job 一次最多查 5 个城市，把 25 个热门城市分成 5 组：

| 组 | 城市 |
|--|--|
| 组1 | 北京、上海、广州、深圳、武汉 |
| 组2 | 西安、杭州、南京、成都、重庆 |
| 组3 | 东莞、大连、沈阳、苏州、昆明 |
| 组4 | 长沙、合肥、宁波、郑州、天津 |
| 组5 | 福州、青岛、济南、哈尔滨、长春 |

只需打开 5 次页面做 WAF 验证，速度提升 5 倍。

### 第五步：加防封策略

- 每页翻页间隔 3-8 秒随机
- 每组之间休息 15-30 秒
- 页面内随机滚动、鼠标移动，模拟真人浏览
- 每组最多爬 15 页
- 连续 3 次接口报错自动暂停 60 秒

## 问题与解决

| 问题 | 解决方案 |
|------|---------|
| F12 打开页面卡死 | 放弃 F12，改用 `chrome://net-export` 系统抓包 |
| Python requests 被 WAF 拦截 | 换 Selenium，在浏览器里用 fetch 调接口 |
| fetch 报编码错误 | 删掉自定义 Referer，让浏览器自动带 |
| Chrome 驱动版本对不上 | 换 Edge + msedgedriver.exe |
| 担心被封 IP | 加随机延迟、滚动模拟、组间休息、页数限制 |
