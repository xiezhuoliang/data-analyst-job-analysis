## 工作流程

### 第一步：找接口

- 原计划用 F12 抓包，但 51job 前端有反调试，一打开 F12 就无限弹 debugger，页面卡死。
- 改用 Chrome 自带的 `chrome://net-export` 录网络日志（系统层面抓，JS 检测不到）。
- 录完后导出 .json，用 Python 解析，成功定位到搜索数据接口（search-pc）。

### 第二步：分析接口参数

- `jobArea` 是城市代码，一次可传 5 个城市，逗号隔开
- `sign`、`user-token`、`uuid` 等鉴权参数相互绑定，需从真实会话中提取
- 加密签名参数会过期，纯 requests 请求过一会儿就被 WAF 拦截

### 第三步：应对 WAF 风控

- 放弃纯 requests，改用 **Selenium + Edge**
- 先打开搜索页让浏览器自动完成风控验证，然后在页面环境里发请求调接口
- 浏览器自带的 Cookie、签名全在，请求看起来就是正常浏览行为
- **踩坑**：手动写了 Referer 头，含中文报编码错。删掉自定义 Referer，让浏览器自己带，问题解决

### 第四步：确定 25 个城市分组

平台一次最多查 5 个城市，把 25 个热门城市分成 5 组：

| 组 | 城市 |
|--|--|
| 组1 | 北京、上海、广州、深圳、武汉 |
| 组2 | 西安、杭州、南京、成都、重庆 |
| 组3 | 东莞、大连、沈阳、苏州、昆明 |
| 组4 | 长沙、合肥、宁波、郑州、天津 |
| 组5 | 福州、青岛、济南、哈尔滨、长春 |

只需打开 5 次页面做验证，速度提升 5 倍。

### 第五步：稳定性策略

- 翻页随机间隔，组间休息
- 页面内随机滚动，模拟真人浏览
- 单组页数设上限
- 连续接口报错自动暂停

## 问题与解决

| 问题 | 解决方案 |
|------|---------|
| F12 打开页面卡死 | 放弃 F12，改用 `chrome://net-export` 系统抓包 |
| Python requests 被 WAF 拦截 | 换 Selenium，在浏览器页面环境里发请求 |
| 请求报编码错误 | 删掉自定义 Referer，让浏览器自动带 |
| Chrome 驱动版本对不上 | 换 Edge + 对应版本驱动 |
| 担心触发风控 | 随机间隔、行为模拟、组间休息、页数限制 |
